# Heart Studio — برنامجنا الخاص للقلب

برنامج لينكس واحد يجمع كل ما يعمل عندنا بالفعل في مكان واحد:

- **المحرك (engine/)** — محرك أفلام الكرتون ثلاثي الأبعاد كما هو، دون أي تعديل.
- **صفحة التحكم (ui/)** — صفحة عربية داكنة تدير بها الفيلم: الفكرة، نص الفيلم،
  مراحل التنفيذ الست (كتابة السيناريو · إضافة الصوت · تشغيل ومعالجة الصوت ·
  بناء المشاهد · خلط المؤثرات والموسيقى · تصدير الفيديو)، مراجعة اللقطات
  والموافقة عليها أو رفضها، والفيلم النهائي وسجل الأحداث.
- **الخادم (server/)** — خادم Node محلي بلا أي مكتبات خارجية: يقدّم صفحة
  التحكم وصفحة عرض المشروع، ويحفظ حالة اللوحة في `panel_state.json` داخل
  مجلد المشروع نفسه.
- **واجهة النماذج (mcp/)** — خادم MCP ومساعد يصلان البرنامج بواجهة نماذج
  APInex، فيستشير النماذج ويراجع عمله بنفسه من الداخل (انظر «نموذج
  التشغيل» أدناه).
- **مهارة البناء (skills/)** — مهارة cartoon-shorts التي تقود خطوات البناء.
- **مشروع تجريبي (projects/demo-ring/)** — فيلم «الخاتم اللي اتدحرج» كاملاً
  كمشروع جاهز للفتح والتجربة.

يعمل على Debian وKali Linux وأي نظام فيه Node.js وChromium — بلا ويندوز،
وبلا أي اشتراكات.

## التثبيت (أمر واحد)

```bash
bash install.sh
```

يفحص Node أولاً: أمر `heart still` يحتاج Node ‏>= 22، فإذا كان Node غير
مثبّت أو أقدم من 22 يعرض المثبّت تحديثه لك تلقائيًا إلى Node 22 عبر
NodeSource — بعد موافقتك وباستخدام sudo — وإن فضّلت التثبيت اليدوي يعرض
لك الأوامر ويتابع: صفحة التحكم و`heart serve` قد يعملان مع الإصدار
الأقدم، لكن `heart still` يحتاج >= 22. ثم يبحث عن Chromium (من ذاكرة
Playwright أو من النظام)، ويضع أمر `heart` في `~/.local/bin`. إعادة
تشغيله آمنة وتحدّث المسارات.

## الاستخدام

```bash
heart serve demo-ring                  # صفحة التحكم: http://127.0.0.1:8903/
heart new my-film                      # مشروع جديد داخل projects/
heart serve my-film
heart still demo-ring 33 frame.png     # لقطة واحدة من الفيلم عند الثانية 33
```

## نموذج التشغيل: النماذج تعمل وتراجع من داخل البرنامج

البرنامج موصول بواجهة نماذج (APInex API) — كما في برنامج Creatorize
الأصلي: القلب لا يعمل وحده، بل النماذج هي التي تبني وتراجع من داخل
البرنامج نفسه، عبر أوامر `heart` وأدوات MCP المدمجة في مجلد `mcp/`.
دور المشغّل (ليلى أو المالك) أن يتفرّج ويقيّم في النهاية بعينه، لا أن
ينقل البرومبتات يدويًا بين البرنامج والنماذج.

```bash
heart models                  # كتالوج النماذج المتاحة عبر الواجهة
heart models glm              # النماذج المطابقة لبحث
heart consult free/glm-5.3 prompt.txt   # استشارة نموذج بملف برومبت
heart critic evidence.txt     # حكم الناقد (GLM) على أدلة البناء:
                              # قياسات اللقطات والسجلات مقابل المعايير
```

### إعداد المفتاح

- **على مكتب ليلى:** يعمل كل شيء تلقائيًا — المساعد المدمج يفوّض إلى
  مساعد الموصل، والمفتاح الحقيقي يمر عبر الخزنة الآمنة ولا يُكتب في
  أي ملف.
- **على جهاز جديد (Kali أو غيره):** عيّن مفتاح APInex بإحدى الطرق:
  متغير البيئة `APINEX_API_KEY`، أو سطر `APINEX_API_KEY=...` في ملف
  `.env` داخل مجلد البرنامج، أو في `~/.heart-studio.env`. المفتاح لا
  يدخل git أبدًا (ملف `.env` مستبعد في `.gitignore`).

### تسجيل MCP لوكلاء القيادة (agy / Claude Code)

```bash
agy mcp add apinex python3 /path/to/heart-studio/mcp/apinex_mcp.py
claude mcp add apinex -- python3 /path/to/heart-studio/mcp/apinex_mcp.py
```

بعد التسجيل تظهر للوكيل أداتان: `apinex_chat` (استشارة أي نموذج،
والافتراضي free/glm-5.3) و`apinex_models` (الكتالوج). التفاصيل الكاملة
في `MCP_INTEGRATION.md`.

## أين تعيش المشاريع؟

كل المشاريع داخل `projects/` بجانب البرنامج. كل مشروع مجلد مستقل فيه
محركه ومشاهده وملفات صوته، وحالة لوحته في `panel_state.json` داخله —
انقل المجلد تنقل المشروع كاملاً.

ملحوظة: تصيير الفيلم الكامل (كل الفريمات) يتم على أسطول التصيير الخارجي
كما هو متبع عندنا؛ البرنامج هنا للتحكم والمعاينة واللقطات المفردة.
