F14 (found in the first live pass exercise): enforceScope compares the project's FULL current git porcelain against the pass's allowedPaths, with no pass-start baseline. A living project legitimately carries uncommitted production state that predates the pass — run outputs under out/, the run's audio/final_mix.wav, a seeded audio/clean.json — and the pass was failed for "scope violations" it did not cause (observed: `scope violation after builder: project:audio/clean.json, project:.heart-git/, project:audio/final_mix.wav, project:out/` on a run where the builder changed nothing). The repo-level check already does this correctly (it diffs against a repoBefore set captured at pass start); the project-level check must do the same.

1. At pass start (same place repoBefore is captured), capture the project's porcelain line set (projectBefore) via gitInProject status --porcelain.
2. In enforceScope, evaluate only project porcelain lines NOT present in projectBefore (the delta the pass actually produced), still flagging any delta path outside def.allowedPaths. Keep the repo-level delta logic unchanged.
3. Hygiene so the delta stays meaningful: at pass start, ensure the project's own .gitignore contains the lines `out/` and `.heart-git/` (append them if missing, creating the file if needed) BEFORE capturing projectBefore — a project's production outputs and its own git dir are never pass-scope material.
