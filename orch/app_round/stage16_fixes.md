F18 (found live): rolling back to the checkpoint that is already HEAD fails with `rollback commit failed`. Sequence: the endpoint checks out the target commit's tree, stages everything, then commits unconditionally — when the worktree already equals the target, the commit has nothing to do, git exits non-zero, and the endpoint 500s on a legitimate no-op state.

Fix: after the `git add -A` that follows the checkout, check the staged diff (the RUN export leg already uses this idiom: `git diff --cached --quiet`, exit 1 = changes present, 0 = none). If there are no staged changes, skip the commit and continue the flow (state resets + success response), adding a note field to the success response such as `note: 'already at target; no commit needed'`. If there are staged changes, commit exactly as today. A non-zero/non-one exit from the diff check itself is still an error.
