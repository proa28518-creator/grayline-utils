Source of props: the owner's visualization bible `~/workspace/user/files/Fudai_Wall_Scene_Visualization_22_7j0z.txt` (approved version). Nothing is added, nothing dropped: if the bible names it, it is on this list.

## Law (from ~/workspace/Production and rules/RULES.md, via driver brief)

- **Prop-truth:** every named prop must be VISIBLY present, framed, and ZOOM-verified in a probe still of THIS project before the board. A frame is real only from a render/probe of this project, viewed zoomed — never from a screenshot, a seat window, or another project.
- **PROP GUARD (RULES.md §4):** a prop that jumps on screen fails the film — `pick_up` / `put_down` / hand-overs / place changes on cuts must hold across the shots where the prop appears.
- **Set bar (RULES.md §5):** each shot ≥ 22 % detailed set and ≤ 80 % flat; film median shot ≥ 28 % detail and ≤ 78 % flat; no more than 40 % of shots under the bar. Environment / Post / Shading cannot finish below it; export refuses below it.
- **Build pass exit (RULES.md pass table):** PROP GUARD passes AND fresh critic YES.
- Prior run failed prop-truth 16/16 on empty probes (sky/sand/caption only). This checklist exists so that failure cannot pass silently again: no scene goes to the board with a PENDING or FAIL prop.

## How a prop is verified

1. Driver renders a probe still per scene (and per major beat where the bible changes the shot).
2. Seat 4 opens the probe, zooms into the prop's frame region, and records: probe file path, zoom verdict PASS/FAIL, and a one-line visual description of what is actually seen.
3. A prop is PASS only when it is identifiable at zoom — right object, right place, right scale relationship (e.g. wall vs 5-storey overlay, wave line stopping at exactly 15M against a 15.5M wall).

Status key: **PENDING** = no probe verified yet · **PASS** = zoom-verified present · **FAIL** = absent / wrong / unframed in probe (blocks the board).
